This is a **source-only** Elova frontend candidate, not authority to build/publish an image on a host, attach Traefik, change the root Compose project, activate a service, issue credentials, publish DNS, or perform a login. The earlier VPS native frontend install was not run. `ops/container/compose.yaml` and `Dockerfile.backend` are **GX10 backend/PostgreSQL only**; do not apply them on the VPS or modify their migrations, secrets, image, volume, or admin. The sibling applications, Traefik root project, and real n8n provider are out of scope. The historical native templates remain unactivated alternatives, not rollback evidence. See [private GX10 route gates](vps-gx10-private-route.md) and [GX10 container runbook](container-runbook.md) for separately owned backend prerequisites; a frontend source change does not prove the backend route is live.

## Source/image custody (later approved operator step; NOT RUN)

`ops/container/Dockerfile.frontend` uses the pinned Node 22 Bookworm slim multi-platform digest and builds only Linux/amd64 from the root lockfile with `npm ci --ignore-scripts`. The build context `.dockerignore` allows only package manifests, the frontend code/config, generated API client, and the runtime guard; no `.env`, credentials, host files, or source-tree `node_modules` are copied. The builder requires an immutable `ELOVA_BUILD_ID` (full reviewed source commit SHA); it has **no** backend URL/build secret. The runtime contains standalone Next.js output and static assets, not build tools or source, and runs as UID/GID 10001. It never runs migrations. CI builds/smokes an **unpushed**, synthetic candidate only on disposable GitHub Linux amd64; local source checks need no Docker.

From a trusted clean checkout of the **merged, approved commit** and its lockfile, independently verify the Node digest's amd64 manifest/config, supported Node version, SBOM/vulnerability policy and build toolchain. Review `.dockerignore`, image recipe, dependencies and CI result. In an approved isolated builder (not GX10), an example build shape is `docker build --platform linux/amd64 -f ops/container/Dockerfile.frontend --build-arg ELOVA_BUILD_ID=<full-reviewed-commit> -t <local-unpublished-tag> .`. Record source commit, lockfile/recipe SHA-256, pinned base manifest and amd64 child digest, builder version, build parameters, scans/SBOM, image ID, signed transfer checksum or immutable registry manifest digest; compare controlled builds or record the reproducibility gap. A local tag is not provenance. **No push or host load is authorized here.** The operator must independently verify transferred artifact checksum/signature and `linux/amd64`, non-root config and image ID against the approval record before setting `ELOVA_FRONTEND_IMAGE` to a verified immutable `name@sha256:<64 hex>` or locally verified `sha256:<image ID>`. `pull_policy: never` prevents an implicit mutable pull.

## Runtime and network decision (later exact VPS/gateway approval; NOT RUN)

`ops/container/compose.frontend.yaml` owns project `elova-frontend` and only the frontend service: no database, backend, host port, published `43180`, external project network, shared volume, or file provider. It creates **two dedicated bridges**, `elova_frontend_proxy` (internal, proxy ingress only) and `elova_frontend_egress` (outbound Tailnet path). The frontend listens at container `0.0.0.0:43180`; there is **no host mapping**. Docker-provider labels default to `traefik.enable=false` even if the gateway has `exposedByDefault=false`. The router is explicitly scoped to `Host(app.elova.dev)`, `websecure`, TLS resolver `mytlschallenge`, service `elova-app` on internal port `43180`, and `traefik.docker.network=elova_frontend_proxy`. Do not copy sibling n8n labels, use `root_default`, route directly to GX10, or assume the separate root-project Traefik is attached to Elova's bridge. Traefik container localhost cannot reach a host-native frontend.

**Stop before route enablement:** an authorized operator must inventory the actual root Compose project/Traefik provider/network settings read-only, verify exact unique router/service/network names and ownership, and decide how to persistently join **only Traefik** to `elova_frontend_proxy` (a reviewed narrow root Compose network attachment or other explicitly approved gateway change). That gateway change is not in this PR. Inspect network isolation and all current sibling attachments; never attach n8n/gotenberg or use a blanket root Compose rewrite. If the operator will not approve a safe persistent attachment, stop: do not use a transient `docker network connect`, root bridge proxy, file provider, or root project rewrite as a shortcut. The dedicated egress bridge must have an explicitly verified route from container to GX10 TCP/43181 on Tailnet, including container DNS (if MagicDNS is chosen), host forwarding/firewall/DOCKER-USER/nftables and IPv4/IPv6 behavior. Tailnet device/ACL grants must allow only the approved VPS principal and deny other peers, LAN and public sources; do not add a GX10/public/DB port or assume Docker network membership is a security boundary. Verify denied-source probes **before** public routing. Document the source identity and exact policy; do not infer it from an IP alone.

The only required runtime file is an **operator-created protected absolute path** supplied as `ELOVA_FRONTEND_ENV_FILE`. It should contain exactly `ELOVA_BACKEND_URL=http://<verified-private-GX10-Tailnet-IP-or-qualified-MagicDNS>:43181` (never commit a value). The BFF validates private Tailnet HTTP origin/port and proxies only same-origin `/api/v1/*` to `/v1/*`; no `NEXT_PUBLIC_` backend URL. Deliver the file only on the authorized VPS, root-owned and readable only to its Compose operator, outside source/build context; never print its contents via `docker compose config`, logs, diagnostics, tickets or CI. Docker environment/inspect can expose the URL to Docker administrators: it is a **credential-free** private origin, not a password. No database URL, session/credential key, n8n token, or owner password belongs on the VPS. The entrypoint refuses missing backend configuration or any `ELOVA_DEV_HTTP_COOKIE_ORIGIN` (even empty), `NEXT_PUBLIC_*`, database URL or backend keys. HTTPS cookies remain `Secure; HttpOnly; SameSite=Strict`; leave the HTTP development exception **absent**. Verify the effective runtime env names without printing values. Restrict Docker socket/project permissions and logs. The service is read-only with non-root UID/GID 10001, no capabilities/privilege escalation, PID/memory/CPU limits, bounded writable tmpfs for Next cache and `/tmp`, no restart-by-default. Confirm resource pressure and disk/log quotas separately. Liveness is local `/health/live`; readiness `/health/ready` and browser `/api/v1/health/ready` require backend/database/migration readiness, not merely a running process.

## Staged rollout and rollback (operator checklist; every step NOT RUN)

1. Get exact VPS identity, independent SSH host-key proof and a separately approved window/owner. **Read-only inventory first**, including any files an operator-run Codex may already have changed: installed native frontend unit/release/env, listeners on IPv4/IPv6 port 43180, running containers/project networks/labels, root gateway and certificates/router state, DNS, current GX10 route, firewall/ACL, image/secret custody, sibling baselines. Never assume an empty VPS or remove an incumbent. Record previous state and exact rollback owner before mutation.
2. Resolve provenance, approved bridge/Traefik attachment and egress policy as above. Preserve root project's non-Elova routers, n8n/gotenberg, GX10 backend and PostgreSQL. Keep DNS A `app.elova.dev` → `69.62.114.160` **prepared/not published**. DNS, public TLS/ACME and external networking are distinct later approvals. Check 443/TLS-ALPN-01 for `mytlschallenge`, Traefik Docker provider `exposedByDefault=false`, router name collisions, certificate state and DNS/cutover order. Do not enable router or publish DNS while route/backend isolation or cert readiness is unproven.
3. In the approved window only, stage the verified image and protected runtime file, review Compose model without emitting env values, inspect Docker UID/limits/ports/networks, then start **only** the Elova frontend with Traefik exposure disabled. Prove container-to-GX10 DNS and private TCP/43181 access using approved checks and BFF readiness (backend `/v1/health/ready` HTTP 200 with `X-Elova-Api-Version: 1`, database and migrations ready). Test unauthorized source denial and no public host TCP/43180 or 43181 introduced. Failure means stop; do not expose an unhealthy frontend.
4. After approved persistent Traefik attachment, TLS/ACME and backend gates, explicitly enable only `ELOVA_TRAEFIK_ENABLE=true` and confirm Docker provider selects the named private network and correct Elova service. With separately approved DNS A publication to `69.62.114.160`, verify HTTPS certificate/SNI/Host routing and same-origin `/api/v1/health/ready`, Secure login cookie through a separately credentialed owner test, browser absence of GX10 URL, and regression checks for all sibling routers and their existing TLS paths. No real owner login or DNS action is part of this PR.
5. On any failure, first disable only the Elova router or restore its recorded pre-change state, then revert only the Elova frontend container/image/runtime file and authorized Traefik network attachment. Restore DNS/certificate routing only under the recorded cutover plan; verify sibling routes and no public Elova 43180/43181. Do not take down root Compose, migrate/recreate GX10 backend/DB, erase volumes, rotate secrets, touch the native unit without inventory, or assume a prior frontend image is compatible. Retain evidence without credential values; escalate if rollback cannot preserve session/backend compatibility.

`npm test` and `npm run lint` run source checks; CI separately proves Linux/amd64 image startup in a disposable runner. Neither cert issuance nor network isolation on real hosts is certified by CI.
